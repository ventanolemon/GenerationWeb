# Расхождение движка между сервером и десктопом

Инвентаризация. Отвечает на вопрос, который нельзя было решать наугад:
насколько разошлись `core/` в GenerationWeb и Generator, и что именно надо
сделать, чтобы свести их обратно.

Повторяется командой `python -m scripts.core_drift` (код выхода 1 при
дрейфе — годится как гейт CI, когда тот появится).

## 1. Почему это не «техдолг», а работающий баг

Графы синхронизируются между десктопом и сервером
(`generation_parametrs`, см. `offline_sync_protocol.md`) и **исполняются по
обе стороны**. Отсюда два отказа, оба живые:

* узла нет на сервере → `/generate` и `/v1/tasks` падают на графе, который
  на десктопе прекрасно работает;
* узел есть с обеих сторон, но с разным кодом → **разное задание из одного
  графа**, без единого сообщения об ошибке.

Инвариант `system_topology.md` §6.5 («один источник каталога узлов»)
фактически нарушен.

## 2. Метод

Сравнение по УЗЛАМ через AST, а не по строкам файлов. Узлы переставляют
внутри модулей и переносят между ними; построчный diff на таком материале
даёт сотни строк шума, в которых тонет единственное важное. Единица
сравнения — класс узла по `type_id`, потому что именно `type_id` едет в
графе по проводу.

## 3. Что нашлось

### Каталог узлов

| | |
|---|---|
| узлов на сервере | 117 |
| узлов на десктопе | **127** |
| идентичны | 86 |
| только на десктопе | 10 |
| только на сервере | **0** |
| один id, разный код | 31 |

**Только на десктопе** — `expr_lambda`, `expr_call`, `expr_reduce`,
`parse_expr`, `subs_expr`, `pick`, `list_concat`, `complex_points_plot`,
`complex_region_plot`, `conformal_map_plot`.

Из 31 расхождения:

* **22 — чистое добавление на десктопе.** Это методы поддержки редактора
  (`summary()` для подписи узла на канве, `TYPE_PARAM`/`TYPE_PARAM_MAP`/
  `type_param_ports()` для вывода типов). Исполнение не затрагивают.
  Решать нечего.
* **9 — взаимное расхождение**: `random_choice`, `list_new`, `expr_subs`,
  `expr_binop`, `compare`, `to_block`, `expr_block`, `formula`,
  `matrix_block`.

### Ключевой вывод по девяти «взаимным»

**Ни одно из них не является форком.** Все девять — эволюция того же узла
на десктопе, с сохранением обратной совместимости; серверные строки в
диффе — это прежние версии изменённых строк, а не потерянная
функциональность. Примеры:

* `compare` — добавлен необязательный параметр `b`: сравнение с константой
  без отдельного узла-числа;
* `formula` — добавлен параметр `constants` (`on`/`off`): трактовать ли
  `c`, `e`, `g`… как физические константы или как обычные переменные;
* `random_choice` — добавлены `count` и `allow_duplicates`, причём автор
  явно оговорил: «при `count=1` выход типизирован как `elem_type` — как
  раньше, обратная совместимость».

Значит **сверка «чья семантика правильная» не нужна**: по каталогу узлов
десктоп однонаправленно впереди.

### Файлы вне каталога узлов — и здесь направление ДРУГОЕ

| файл | кто впереди | что там |
|---|---|---|
| `graph/document.py`, `graph/node.py`, `graph/symbolic.py` | десктоп | развитие движка |
| `latex.py`, `rendering.py`, `registry.py`, `word_stats.py`, `composites.py`, `generator.py` | десктоп | развитие |
| **`blocks.py`, `dynamic_blocks.py`, `content.py`** | **СЕРВЕР** | ленивые Qt-импорты (headless), `to_dict()` для JSON |
| **`task.py`** | **СЕРВЕР** | `state()`/`restore()`, `_safe_meta` |
| `repository.py` | — | разный по построению, см. §4 |

Это и есть главная причина, по которой задачу нельзя закрыть копированием
в любую сторону. У сервера в `blocks.py`/`dynamic_blocks.py` лежит работа,
без которой **ядро не импортируется в headless-окружении**: все Qt-зависимости
загружаются лениво, внутри `render_qt`. Скопируй десктоп поверх — FastAPI
перестанет подниматься без установленного PyQt6.

## 4. Что расходиться ОБЯЗАНО

Не всё различие — дрейф. По построению различаются:

* `core/repo/` и `core/repository.py` — у сервера слой к своей БД со
  схемой RBAC, миграциями и публичным API; у десктопа — к локальной SQLite
  с персональными скрытиями и снимком выдач;
* серверные `*_api.py` (headless-логика) против десктопных `*/client.py`
  (HTTP-клиенты к ним) — это дополняющие половины, а не дубли;
* `session.py`, `settings.py`, `sync/store.py` — только десктопные.

Список ожидаемых расхождений зафиксирован в `scripts/core_drift.py`
(`EXPECTED`), чтобы гейт не шумел на них.

## 5. Что делать

**Свести — это две встречные операции, а не одна.**

1. **Каталог узлов и движок графов: десктоп → сервер, целиком.** Конфликтов
   нет, обратная совместимость соблюдена авторами. Сюда же `latex.py`,
   `rendering.py`, `registry.py`, `word_stats.py`, `composites.py`,
   `generator.py`, `graph/*`.
2. **Headless-адаптации: сервер → десктоп.** Ленивые Qt-импорты и
   `to_dict()` из `blocks.py`/`dynamic_blocks.py`/`content.py`, снимок
   состояния из `task.py`. На десктопе ленивые импорты не мешают ничему, а
   `to_dict()` там просто не вызывается.
3. После этого дерево движка становится побайтово одинаковым, и дальше его
   держит механизм из §6.

**Проверка результата — прогон обоих наборов тестов**: 227 на сервере плюс
десктопные. Первое, что должно сойтись, — что сервер после (1) не потерял
headless: `python -c "from generator_service.main import app"` без PyQt6.

## 6. Как не разойтись снова

Разбор вариантов (монорепо / submodule / пакет / вендоринг) — в
`public_api.md` он не дублируется; коротко: рекомендован **вендоринг с
проверкой дрейфа** как первый шаг, потому что делается сегодня и не требует
релизной инфраструктуры, а `scripts/core_drift.py` уже написан и даёт код
выхода 1.

Предпосылка, которую нельзя пропустить: **в репозитории нет ни одного
CI-воркфлоу**. Пока его нет, гейт придётся запускать руками, и это
единственное, что стоит между «разошлись однажды» и «расходятся дальше».

Долгосрочно правильный ответ — общий версионируемый пакет; он оправдан,
когда появится релизный цикл десктопа.

## 7. Что это меняет в структуре

Причина, по которой расхождение вообще стало возможным, видна из §3:
`blocks.py` держит в одном классе и модель содержимого, и **четыре**
бэкенда рендеринга (Qt, docx, LaTeX, JSON). Серверу понадобился один из
них и не понадобился другой — отсюда и разъехались копии.

Если разделять, то по этому шву: чистая модель блока отдельно, рендереры
отдельно и подключаемо. Это не срочно и в задачу сведения не входит, но
без этого шва копии будут стремиться разойтись снова — уже по другой
причине.
