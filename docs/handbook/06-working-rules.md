# 06. Правила работы

Правил немного, и каждое появилось после конкретной ошибки. Они не про
стиль — про то, что держит проект целым при двух репозиториях, двух
клиентах и общем движке.

---

## 1. Зеркалирование ядра

`core/` существует в двух копиях: `GenerationWeb/core/` и
`Generator/core/`. Переносятся правки руками.

### Что обязано совпадать

Всё, что ИСПОЛНЯЕТ граф: `core/graph/**`, `core/models/**`, правила
равенства (`answers.py`, `boolean_text.py`, `program_output.py`,
`equation_text.py`, `word_tolerance.py`, `pronunciation.py`,
`partition_ids.py`).

Основание: узел, которого нет на сервере, роняет `/generate`; узел с
другим кодом даёт ДРУГОЕ задание, ничего об этом не сообщая.

### Что законно различается

| Файл | Почему |
|---|---|
| `repository.py` | слои доступа к БД у сторон разные по построению |
| `blocks.py`, `dynamic_blocks.py`, `content.py`, `task.py` | серверу нужны ленивые Qt-импорты ради headless |
| `__init__.py` | разный состав экспорта |

Этот список записан в `scripts/core_drift.py` как `EXPECTED` — не для
порядка, а чтобы новое расхождение было ГРОМКИМ.

### Что живёт только на сервере

`core/*_api.py`, `migrations.py`, `signing*.py`, `graph/isolation.py`,
`graph/worker.py` и прочее из списка `SERVER_ONLY`. Файл оттуда,
ОКАЗАВШИЙСЯ на десктопе, — ошибка зеркалирования.

**Случай не гипотетический.** При переносе правок туда уезжали
`content_authz.py`, `sync_api.py` и серверные тесты. Прежняя проверка их
не видела — она сравнивала файл с файлом, а сравнивать было не с чем.
Теперь проверка выводит «серверность» теста механически: тест серверный,
если импортирует то, чего на десктопе нет.

### Проверка

```bash
cd GenerationWeb
python -m scripts.core_drift ../Generator
```

Сравнение по УЗЛАМ через AST, а не построчно: узлы переставляют внутри
модулей и переносят между ними, и построчный diff на таком материале
даёт сотни строк шума.

Код выхода 0 — расхождений нет, 1 — есть.

## 2. Пакеты узлов едут в одну сторону

Пакеты узлов ставятся на сервере и оттуда попадают на десктоп. Обратного
пути нет и не задумано: набор пакетов сервера — предмет решения
администратора, а не результат того, что кто-то поставил себе локально.

## 3. Тесты

### Как запускать

```bash
# сервер
cd GenerationWeb && python -m unittest discover -t . -s . -p "test_*.py"

# десктоп
cd Generator && QT_QPA_PLATFORM=offscreen \
  python -m unittest discover -t . -s . -p "test_*.py"

# фронт
cd GenerationWeb/frontend && npm test
```

**`-t .` обязателен.** `discover -s core` без него ломает относительные
импорты и выдаёт ошибки, которые выглядят как настоящие поломки.

### Чего проверка стоит

Тест, который не падает на старом коде, не проверяет ничего. Поэтому
здесь принят приём «регрессия наоборот»: рядом с проверкой нового
правила стоит проверка, что СТАРОЕ правило на этих же данных
ошибалось.

Примеры в наборе:
`test_the_old_rule_did_collide` (словарь), `test_the_old_scheme_did_diverge`
(номера разделов), `test_the_old_rule_would_pick_the_wrong_wire` (провода),
`test_the_old_fixed_palette_did_fail` (тема холста).

### Набор обязан говорить о себе правду

Был случай: файл `core/test_graph_api.py` давал `unittest discover`
**ноль тестов** — он был написан не в форме `unittest`, — и одно из
утверждений в нём уже не выполнялось. Прогон при этом был зелёный.

Поэтому есть `core/test_suite_completeness.py`: он проверяет, что каждый
файл `test_*.py` действительно даёт тесты.

## 4. Замер вместо рассуждения

Правило простое: **утверждение о поведении подтверждается прогоном или
картинкой, а не чтением кода.**

Что это дало на практике:

| Дефект | Чем найден |
|---|---|
| Подпись провода невидима | сгенерированный снимок: обводка съедала глифы |
| Сырой LaTeX в документации | взгляд на PNG |
| Ссылка на раздел ломала маршрут | клик по собранной странице |
| Нумерованный список схлопывался | взгляд на собранную страницу |
| 17 столкновений (объединённый словарь), 48 (по словарям отдельно) | прогон правила по поставочным словарям |
| Номера разделов разошлись | сравнение двух живых БД |
| Провод выделяется не тот | замер расстояний в спорной точке |

Числа в документах — из таких прогонов. Если число разошлось с тем, что
показывает прогон, верен прогон.

## 5. Документы

* **Установленное и предполагаемое разделены явно.** У дефекта пишется
  отдельно «что установлено» и «что НЕ установлено».
* **Цифры именуют источник.** «17 пар на объединённом словаре (160
  слов)», а не «много».
* **Решение записывается вместе с основанием.** Иначе через полгода его
  отменят как непонятную странность — см. [05](05-what-not-to-do.md).

## 6. База знаний

Живёт в `docs/guide/*.md`, собирается в `frontend/src/guide/content.json`.

* **Якоря объявляются явно** и лежат в `anchors.json`. Не выводятся ни из
  заголовка, ни из имени файла: опубликованная ссылка не должна ломаться
  от переименования заголовка.
* **Набор разметки закрыт.** Неизвестная конструкция — ошибка разбора.
* **Снимки генерируются**, а не делаются руками: `scripts/guide_shots.py`,
  реестр `shots.json`.

Пересборка:

```bash
python -m scripts.guide_export     # markdown → content.json
python -m scripts.guide_shots      # перегенерировать снимки
```

## 7. Поставочные ресурсы

`resources/` — то, что уезжает пользователю: словари, звук,
транскрипции, шаблон БД.

**Файл БД — ресурс, а не рабочий файл.** Запуск проекта из рабочей копии
его меняет. Перед коммитом проверять `git status`; на страже стоят
`tests/test_shipped_database.py`, `.gitattributes` и игнор хвостов
журнала.

Звук и транскрипции пересобираются отдельно и в рантайме не нужны:

```bash
python tools/generate_transcriptions.py    # IPA из CMUdict
python tools/generate_audio.py             # WAV через espeak-ng
```

## 8. Учётные записи для работы

```bash
python -m scripts.seed_accounts
```

Заводит `dev` и `owner` с полным доступом. Пароли лежат в репозитории
открытым текстом — **перед выкладкой наружу их надо сменить**:

```bash
python -m scripts.seed_accounts --dev-password … --owner-password … --reset-password
```

Скрипт печатает это предупреждение на каждом запуске. Намеренно.
