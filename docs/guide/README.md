# База знаний: как она устроена

Это не «папка с текстами», а формат с двумя правилами, каждое из которых
отвечает на конкретную неприятность.

## Правило 1. Адрес фрагмента объявлен, а не выведен

Якорь **никогда** не выводится ни из заголовка, ни из имени файла.
Каждый файл объявляет свой `id`, каждый раздел — свой:

```md
---
id: getting-started
title: С чего начать
order: 1
---

## Вход и роли {#roles}
```

Полный адрес — `getting-started/roles`. Он переживает переименование
файла и правку заголовка, потому что не зависит ни от того, ни от
другого.

Зачем так. Ссылки на документацию расходятся по чатам, письмам и чужим
материалам. Якорь, выведенный из заголовка, ломается на первой же правке
формулировки — а править формулировки в документации приходится
постоянно, и ломаться они будут молча.

**Реестр.** `anchors.json` перечисляет все известные адреса. Новый раздел
надо в него внести; исчезнувший роняет проверку. Это не бюрократия: адрес,
который однажды опубликовали, нельзя убрать «между делом», а увидеть его
пропажу иначе неоткуда.

## Правило 2. Снимки экрана генерируются

В тексте снимок ставится **по идентификатору**, а не по пути к файлу:

```md
![Экран генератора](shot:generator-main)
```

Картинки делает `scripts/guide_shots.py` и складывает в
`frontend/public/guide/`. Руками положенный файл проверку не пройдёт: он
не значится в `shots.json`, который пишет тот же скрипт.

Зачем так. Снимок, снятый руками, устаревает молча: на картинке остаётся
кнопка, которой в продукте больше нет, и ни один тест этого не покажет.
Сгенерированный пересобирается вместе с интерфейсом.

## Правило 3. Набор разметки закрыт

Абзац, список, врезка кода, `**жирный**`, `` `код` ``, ссылка `guide:`,
картинка `shot:` — и всё. Таблица, цитата, заголовок четвёртого уровня,
картинка по пути, ссылка не через `guide:` — **ошибка разбора**, а не
«покажем как есть».

Зачем так. Клиент показывает ровно это подмножество; конструкция, которую
он не знает, вылезла бы на страницу сырым текстом. Ровно так однажды и
вышло: нумерованный список схлопнулся в один абзац, и увидеть это можно
было только глазами на собранной странице.

Расширять набор можно — но только вместе с рендерером и списком
запрещённого, а не «мы же просто добавим таблицу».

**Отдельно про ссылки.** `guide:` с недопустимым адресом (кириллица,
пробел, заглавные) до недавнего времени проходил насквозь: под запрет
«ссылки не через guide:» не попадал, в список ссылок не извлекался — и
оставался на странице сырым текстом со скобками. Теперь такой адрес
роняет разбор.

## Правка из приложения

Администратор и разработчик правят страницы **прямо в базе знаний**, не
трогая репозиторий: кнопка «Править» на странице.

Правки хранятся ПОВЕРХ поставки (`core/guide_store.py`, таблица
`guide_pages`), а не вместо неё. Файлы здесь остаются умолчанием, и
именно они попадают в сборку — база знаний обязана открываться у гостя и
без сети, то есть ровно тогда, когда что-то не работает.

Что это значит для того, кто правит ФАЙЛЫ:

* правка из приложения ПЕРЕКРЫВАЕТ файл. Изменили файл, а страница
  выглядит по-старому — посмотрите, нет ли на ней пометки «правлена в
  приложении», и снимите правку кнопкой «Вернуть поставочную»;
* правка проходит те же три правила, что и файл. Отказ приходит с
  причиной: «таблицы веб-клиент не показывает»;
* новые страницы из приложения не заводятся — только здесь, вместе с
  записью в `anchors.json`.

## Проверки

```
python -m unittest core.test_guide core.test_guide_store
```

Что проверяется: у каждого файла и раздела есть объявленный `id`; адреса
уникальны; реестр совпадает с содержимым; каждая ссылка `shot:` ведёт на
существующий сгенерированный снимок; внутренние ссылки указывают на
существующие адреса; правка из приложения проходит те же правила и не
может завести страницу мимо реестра.
