## 1. Что это такое

Система генерации **вариантов учебных заданий** с автоматической
проверкой ответа. Преподаватель описывает задание один раз — дальше
система порождает сколько угодно непохожих вариантов и проверяет ответы
студентов сама.

Ключевое отличие от «банка задач»: **правильный ответ хранится не
строкой, а описанием того, что считать правильным** (`AnswerSpec`).
Поэтому `2x` и `x+x` — один ответ, `A и B` и `B ∧ A` — один ответ, а
опечатка принимается ровно до тех пор, пока не становится другим
допустимым ответом.

Задание описывается **графом вычислений** (145 узлов в каталоге), который
исполняется одинаково на сервере и на десктопе.

Шесть дисциплин: линейная алгебра, матанализ, физика, ОПВС, информатика,
английский.

### Два репозитория, одно ядро

| Репозиторий | Что это | Как запускается |
|---|---|---|
| **`ventanolemon/GenerationWeb`** | сервер (FastAPI ×2), веб-клиент (React), `web_layer` (ASP.NET), **общее ядро** | службы + браузер |
| **`ventanolemon/Generator`** | настольное приложение (PyQt6) с **зеркальной копией** ядра | `python main.py` |

Копия ядра **не автоматическая** — правки переносят руками, расхождение
ловит `python -m scripts.core_drift ../Generator`.

Локально оба лежат рядом: `/home/user/GenerationWeb` и `/home/user/Generator`.

## 2. Прочитать ДО первой правки

Семь правил. Каждое появилось после конкретной ошибки, и каждое дороже
всего стоит, когда его нарушают не зная.

**1. В `resources/` из прогона не пишут. Никогда.**
Это ПОСТАВКА: словари, звук, транскрипции и **шаблон** базы. В разовых
сценариях `Repository` открывают на КОПИИ (`core/tmpdb.temp_path()` +
`shutil.copyfile`). Заслон стоит в `test_shipped_database.py` — он
сравнивает `git status -- resources` с пустотой.
*Случалось четырежды за одну работу; однажды прогон удалил восемь
поставочных WAV.*

**2. Рабочая база и поставка — разные файлы.**
`resources/users_database.db` — только чтение. Рабочая живёт в
`GEN_DATA_DIR` (по умолчанию `data/`) и создаётся копией шаблона при
первом запуске (`const.ensure_data_dir`, идемпотентно). `data/` в
`.gitignore`.

**3. Временную БД в тесте заводят через `temp_path()`** (`core/tmpdb.py`),
а не `tempfile.mktemp`/`mkstemp`. SQLite держит рядом `-wal` и `-shm`, и
они переживают удаление базы. *Накопилось 37 065 пар на 29 ГБ, диск встал
на 100%, прогон дал 144 ошибки при исправном коде — и это выглядело как
регрессия в правке, к которой отношения не имело.*

**4. Ядро зеркалится целиком — и то, чем оно пользуется, тоже.**
Правку в `core/` переносят в оба репозитория. Что законно различается —
список `EXPECTED` в `scripts/core_drift.py`; что живёт только на сервере —
`SERVER_ONLY`. *`tmpdb.py`, положенный в разные места, сразу сломал
зеркалимый тест.*

**5. `unittest discover` требует `-t .`**, десктоп — `QT_QPA_PLATFORM=offscreen`.
Без первого ломаются относительные импорты, и ошибки выглядят как
настоящие поломки.

**6. Утверждение о поведении подтверждается ПРОГОНОМ, а не чтением кода.**
Числа в документах — из замеров. Если число разошлось с прогоном, верен
прогон. Догадку от установленного факта отделяют явно: «не
воспроизведено», «причина неизвестна».

**7. Тест, который не падает на старом коде, не проверяет ничего.**
Принят приём «регрессия наоборот»: рядом с проверкой нового правила
стоит проверка, что старое на этих же данных ошибалось.

Подробно: [`docs/handbook/05-what-not-to-do.md`](docs/handbook/05-what-not-to-do.md),
[`06-working-rules.md`](docs/handbook/06-working-rules.md).

## 3. Устройство

```
        браузер                      настольное приложение
           │                                   │
        nginx                                  │ своя БД, работает
           │  /api                             │ без сети, потом
       web_layer  (ASP.NET)                    │ синхронизируется
      │              │                         │
      │              └──────────┐              │
 generator_service         contour_service
   (FastAPI, движок)        (FastAPI, LLM-петля)
      │                          │
      └────────── SQLite ────────┘   ← GEN_DATA_DIR, том в контейнере
```

Порты зависят от способа запуска, и это единственное, что между ними
различается:

| | разработка | развёртывание |
|---|---|---|
| точка входа | Vite `:5173` | nginx `:8080` |
| `web_layer` | `:5000` | `:8080` внутри сети |
| `generator_service` | `:8000` | `:8000`, наружу **не** проброшен |
| `contour_service` | `:8001` | `:8001`, наружу **не** проброшен |

**`web_layer` — единственный, кто разбирает сессию и назначает роль.**
Python-службы — приватная сеть: личность приходит к ним заголовками
`X-User-Id` / `X-User-Role`, которые ставит `web_layer`. Достучись до них
браузер напрямую — он ставил бы их сам, и роль перестала бы что-либо
значить. В развёртывании портов у них нет вовсе, а nginx срезает эти
заголовки на входе.

**Весь `/api` идёт через `web_layer` — и в разработке, и в бою.** Особых
правил Vite для отдельных префиксов больше нет: пока путь разработки
отличался от боевого, сломанный релей нельзя было заметить раньше
продакшена (так было с `/api/graph` — редактор графов разворачивался
только вместе с dev-сервером).

### Где что лежит (`GenerationWeb`)

| Путь | Что там |

## 4. Как запускать серверную часть

Python 3.11. Все команды — **из корня `GenerationWeb`** (иначе не найдутся
`const` и `core`).

```bash
pip install -r requirements.txt
```

### Вариант А. Быстро, без .NET

Хватает для разработки фронта и движка. `web_layer` — тонкий прокси, и
его можно не поднимать.

```bash
# терминал 1
uvicorn generator_service.main:app --host 127.0.0.1 --port 8000

# терминал 2
cd frontend && npm install
VITE_API_DIRECT=1 npm run dev
```

Открыть **http://localhost:5173**. Движок жив: http://127.0.0.1:8000/docs

`VITE_API_DIRECT=1` шлёт весь `/api` прямо на FastAPI со срезанным
префиксом — маршруты совпадают, потому что `web_layer` их не меняет.

### Вариант Б. Полный состав

```bash
uvicorn generator_service.main:app --host 127.0.0.1 --port 8000   # движок
uvicorn contour_service.main:app  --host 127.0.0.1 --port 8001    # LLM-петля
cd web_layer && dotnet run                                        # :5000
cd frontend  && npm run dev                                       # :5173
```

Открыть **http://localhost:5173** (Vite переадресует `/api` на `:5000`).
Адреса служб для `web_layer` — в `web_layer/appsettings.json`.

`contour_service` нужен только для LLM-контура и куратора корпуса;
без него остальное работает.

### Вариант В. Развёртывание (четыре контейнера)

```bash
cd deploy
cp .env.example .env      # ОТРЕДАКТИРОВАТЬ: там пароли и ключи
docker compose up --build
```

Открывается на **http://localhost:8080**. Наружу смотрит только nginx.
Рабочая база — на томе; `resources/users_database.db` в образе это
шаблон, с которого том наполняется при первом запуске.

Честный список того, для чего пример **не** годится (SQLite вместо
Postgres под очередью, нет TLS, нет резервных копий, одна реплика) —
[`deploy/README.md`](deploy/README.md).

### Учётные записи

```bash
python -m scripts.seed_accounts          # заведёт dev и owner
python -m scripts.seed_demo              # демо-наполнение (не обязательно)
```

**Пароли по умолчанию лежат в репозитории открытым текстом.** Перед
выкладкой наружу:

```bash
python -m scripts.seed_accounts \
    --dev-password '…' --owner-password '…' --reset-password
```

Скрипт печатает это предупреждение при каждом запуске — намеренно.

### Переменные окружения, которые стоит знать

| Переменная | Смысл |
|---|---|
| `GEN_DATA_DIR` | каталог рабочих данных (по умолчанию `data/`) |
| `GEN_DB_PATH` | путь к базе целиком, если он задаётся отдельно |
| `GENERATOR_CORS_ORIGINS` | через запятую, если фронт на другом порту |
| `CONTOUR_PROVIDER` | `mock` (без сети и денег) или `anthropic` |
| `ANTHROPIC_API_KEY` | для боевого провайдера контура |
| `CONTOUR_PG_DSN` | Postgres вместо SQLite под очередью |
| `GEN_TRUST_IDENTITY_HEADERS` | **переходный режим, включать не надо** — роль в заголовках не заверена |

Подробно: [`docs/handbook/07-running-it.md`](docs/handbook/07-running-it.md).

## 5. Проверки

```bash
# сервер: 1684 теста
cd GenerationWeb && python -m unittest discover -t . -s . -p "test_*.py"

# десктоп: 2328 тестов
cd Generator && QT_QPA_PLATFORM=offscreen \
  python -m unittest discover -t . -s . -p "test_*.py"

# фронт: 86 тестов
cd GenerationWeb/frontend && npm test && npm run build

# расхождение ядра между репозиториями
cd GenerationWeb && python -m scripts.core_drift ../Generator
```

Всего **4098** автоматических проверок. Прогон сервера ≈150 с, десктопа
≈100 с.

**Тесты в двух репозиториях лежат по-разному**, и это сбивает: у сервера
они в `core/test_*.py` (рядом с кодом), у десктопа — в `tests/`. Оттуда и
правило про `core/tmpdb.py`: помощник, которым пользуется зеркалимый
тест, обязан лежать в зеркалимом месте.

### Быстрая проверка, что окружение живо

Минута, и сразу видно, всё ли на месте:

```bash
python -c "import PyQt6, numpy, sympy, fastapi; print('зависимости на месте')"
python -m unittest core.test_voice_answer      # 57 тестов, ~2 с
python -m scripts.core_drift ../Generator      # «Расхождений нет»
git status --porcelain -- resources            # должно быть ПУСТО
```

### Пересборка производного

Не пересчитывается в рантайме — после правки надо запускать руками:

```bash
python -m scripts.guide_export     # docs/guide/*.md → content.json для фронта
python -m scripts.guide_shots      # снимки для базы знаний
python -m scripts.export_openapi   # описание HTTP API
```

Адрес нового раздела базы знаний надо внести в `docs/guide/anchors.json` —
иначе `core.test_guide` упадёт. Это заслон против ломающихся ссылок, а не
придирка.

* **Поставка и данные разведены.** `resources/users_database.db` стал
  шаблоном, рабочая база — в `GEN_DATA_DIR`. Закрыт МЕХАНИЗМ дефекта

* **Собран пример развёртывания** `deploy/`: nginx + web_layer + две
  Python-службы + том. Проверен запуском тех же процессов напрямую (весь
  путь браузера, срезание заголовков личности); `docker build` **не**

* **Раздела произношения на сервере не было вовсе** — генератор был, в
  `bootstrap` не подключён. Разделов 19, генераторов 114 вместо 95.

* **Вложенные организации**: `parent_id` принимался и записывался, а
  читать его некому. Теперь 400 с объяснением.
* **Утечка временных БД в прогоне закрыта** (см. правило 3 выше).
* Раньше в этой же работе: порог уверенности произношения выведен из

## 8. Что осталось

### Ждёт сведений, а не работы

| Что | Что нужно |
|---|---|
| Падение десктопа `0xC0000374` при правке формулы | стек следующего падения — `faulthandler` уже включён, `GEN_CRASH_LOG=путь python main.py` |
| Прямоугольник поверх интерфейса в левом верхнем углу | повторяется ли при каждом открытии редактора; исчезает ли при изменении размера окна |

### Отложено решением

* **Токен в `localStorage`.** Правильно — httpOnly-cookie плюс защита от
  CSRF, но это меняет протокол между фронтом, `web_layer` и десктопом.
  Ждём требований по безопасности развёртывания.

### Не построено

* **Загрузка своих файлов автора** (`blob:sha256-…`, адресация по
  содержимому). Спроектировано целиком —
  [`docs/architecture/user_resources.md`](docs/architecture/user_resources.md),
  шесть шагов, первые четыре дают работающую загрузку. В этот примитив
  упираются: свой словарь или картинка автора, сохранённая настройка
  дашборда, картинка в загруженной странице базы знаний.
* **Справочник по каждому узлу языка** — писать стоит, когда узлы
  перестанут добавляться.
* **Контекстная установка пакетов** («нужен пакет X» → кнопка
  «Установить») — небольшой кусок поверх готового.

### Проверено чтением, а не прогоном

Это не «сделать», а «знать»:

* `web_layer` собирался и запускался на **SDK 8**, а проект объявляет
  `net10.0` — прогон шёл на копии с подменённым `TargetFramework`, сам
  `csproj` не тронут;
* **образы контейнеров не собирались** — нет демона Docker;
* LLM-часть контура на живой модели не гонялась (тесты идут на `mock`);
* офлайн-синк вживую («неделя без сети, потом слияние») не проходили.

## 9. Git

Работа идёт в **обоих** репозиториях на ветке
`claude/generation-web-subject-grants-wap7ud`; на неё открыты черновые
pull request'ы (GenerationWeb #22, Generator #41).

Порядок правки, затрагивающей ядро:

1. правка в `GenerationWeb/core/`;
2. перенос в `Generator/core/` (обычно `cp` затронутых файлов);
3. `python -m scripts.core_drift ../Generator` — должно быть «Расхождений нет»;
4. оба прогона;
5. `git status -- resources` в обоих — должно быть пусто;
6. коммит в оба репозитория, пуш в обе ветки.

Сообщение коммита объясняет ПРИЧИНУ, а не перечисляет файлы: двоичный
diff и список путей сами ничего не объяснят через полгода.
